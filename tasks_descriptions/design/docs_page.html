Architecture

Hyper Stack Manager operates on a decentralized, modular architecture designed for modern hybrid stacks. Understand the core components that power the environment hypervisor.

01. LEGO-ARCHITECTURE PRINCIPLE

Unlike monolithic orchestrators, Hyper Stack treats every service as an independent block. The architecture is composed of three primary layers: the Control Plane, the Data Plane, and the Plugin Interface.

02. MANIFEST CONFIGURATION

The core of the architecture is defined in the hyper.yaml manifest. This file dictates how the atomic synchronization engine resolves dependencies.

terminal ~/project/hyper.yaml 
# Hyper Stack Configuration v3
version: "3.1"
project:
  name: "quantum-dashboard"
  env: "production"
services:
  vector-db:
    image: "qdrant/qdrant:latest"
    ports:
      - 6333:6333
    volumes:
      - "./data:/qdrant/storage"
    healthcheck:
      test: ["CMD", "/healthz"]
      interval: "30s"
  backend-api:
    build: "./api"
    depends_on:
      - "vector-db"
    environment:
      HYPER_SYNC_MODE: "atomic" # Ensures transactional updates
info

Developer Note

The architecture supports hot-swapping components. You can replace the vector DB implementation in the manifest without rebuilding the entire stack if the interfaces match.
