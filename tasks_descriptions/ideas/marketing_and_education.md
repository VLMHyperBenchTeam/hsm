# Идея: Маркетинг и Обучение (Marketing & Education)

> [!NOTE] Source: feedback_2026-02-14_06-01-01.md
> **User Insight**: Пользователи не понимают ценность проекта из сложной документации. Нужен "Elevator Pitch", простые аналогии (конструктор, кубики) и четкое позиционирование.

## 🎯 Цели
1.  **Упрощение входа**: Снизить когнитивную нагрузку для новых пользователей. Объяснить сложные концепции (оркестрация, изоляция) простым языком.
2.  **Визуализация**: Использовать диаграммы и схемы для демонстрации архитектуры "Проект-Конструктор".
3.  **Обучение через практику**: Создать серию коротких туториалов, решающих конкретные боли (замена БД, добавление библиотеки).

## 📝 Концепции для контента

### 1. Проект-Конструктор (The Builder Concept)
*   **Метафора**: Проект — это не монолит, а набор слотов, в которые вставляются кубики-компоненты.
*   **Термины**:
    *   **Компонент**: Кирпичик (Пакет / Сервис).
    *   **Намерение (Intent)**: "Хочу заменить кубик А на кубик Б".
    *   **Реализация (Implementation)**: HSM сам перестраивает связи.

### 2. Сценарии использования (Use Cases)
*   **Разработчик**: Быстрое переключение между dev (код) и prod (образ) режимами.
*   **ML-инженер**: Эксперименты с разными версиями библиотек и моделей без поломки окружения.
*   **Team Lead**: Гарантия идентичности окружения у всей команды через единый `hsm.yaml`.

### 3. Сравнение (Comparison)
*   **HSM vs Git Submodules**: Гибкость версий, on-demand загрузка, чистота репозитория.
*   **HSM vs UV Workspaces**: Поддержка Docker, работа с удаленными репозиториями, управление инфраструктурой.
*   **HSM vs Docker Compose**: Динамическая генерация конфигов, управление Python-пакетами.
