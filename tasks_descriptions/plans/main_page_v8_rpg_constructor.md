# HSM: Hyper Stack Manager

**HSM** — это Meta-Orchestrator для современной разработки, выступающий в роли "Environment Hypervisor". Он позволяет декларативно собирать рабочее окружение проекта из независимых компонентов (библиотек и сервисов) на основе единого манифеста.

---

## 🧩 Концепция: Проект как Конструктор

Мы предлагаем смотреть на архитектуру проекта как на **RPG-персонажа**, где каждый функциональный блок — это **слот** для установки "кубика-компонента".

![Проект как Конструктор](concept-constructor.png)

### 1. Слоты и Интерфейсы (Slots)
Ваш проект взаимодействует с внешним миром через **абстрактные интерфейсы**. 

В терминологии конструктора — это "посадочные места" (слоты).
*   `vector-db-client` — слот для работы с векторной БД.
*   `emb-client` — слот для получения эмбеддингов.

### 2. Магазин кубиков (Registry)
**Реестр HSM** — это витрина доступных компонентов. Каждый кубик в реестре — это отдельный Git-репозиторий, который может быть:
*   **Библиотекой** (Python-пакет).
*   **Сервисом** (Docker-контейнер или изолированный `uv venv`).

### 3. Умные связи и Группы (Implies & Groups)
Реестр знает о зависимостях между кубиками. Это позволяет реализовать механику "автоматического снаряжения":
*   **Группы 1-of-N**: Слот, в который можно вставить только одну реализацию (например, либо `qdrant`, либо `milvus`).
*   **Implies (Синергия)**: При выборе кубика `qdrant-client` (библиотека), HSM автоматически устанавливает в связанный слот инфраструктуры кубик `qdrant-service` (контейнер).

---

## ⚔️ Механика работы: Намерение и Реализация

HSM разделяет архитектурное решение и его техническое воплощение.

### 1. Намерение (Intent)
Вы не правите конфиги `docker-compose` или `pyproject.toml` вручную. Вы сообщаете системе свое намерение через CLI. Это ваш **Заказ на сборку**.
```bash
# "Экипировать проект клиентом Milvus"
hsm select vector-db milvus
```
HSM записывает это в **Манифест** (`hsm.yaml`) — главный чертеж вашего "билда".

### 2. Реализация (Implementation)
Команда `hsm sync` запускает **Engine**, который материализует чертеж в реальное окружение:
*   **В Проекте**: Управляет Python-пакетами через адаптер `uv`.
*   **В Инфраструктуре**: Поднимает нужные Docker-контейнеры или VES-сервисы.
*   **Связи**: Автоматически пробрасывает ENV-переменные (HOST, PORT) между компонентами.

## 📦 Состояния компонента: Prod vs Dev

Каждый кубик в вашем конструкторе может находиться в одном из двух режимов, которые переключаются "на лету":

*   📦 **Prod (Закрытая коробка)**: Использование готового артефакта (Docker-образ или пакет из PyPI). Максимальная стабильность.
*   🛠 **Dev (Открытая коробка)**: HSM скачивает исходный код компонента, подключает его к проекту как `editable` и настраивает **Hot-Reload**. Вы правите код компонента — изменения мгновенно применяются в работающей системе.

---

## 🚀 Ключевые фишки

*   **VES (Virtual Environment Services)**: Полная изоляция Python-сервисов. Забудьте о конфликтах зависимостей (например, Pydantic v1 и v2) в рамках одного проекта.
*   **Atomic Sync**: Синхронизация — это транзакция. Если что-то пойдет не так (конфликт версий, ошибка сети), HSM откатит изменения, сохранив проект в рабочем состоянии.
*   **Hybrid Stack**: Единое управление для Python-кода и Docker-инфраструктуры.

## 🏁 Быстрый старт

```bash
# 1. Установка
uv tool install git+https://github.com/VLMHyperBenchTeam/hsm.git

# 2. Инициализация
hsm init

# 3. Сборка конструктора
hsm sync
```
