# Task: Обновление SyncEngine для поддержки VES

## Контекст
SyncEngine должен научиться материализовать сервисы-репозитории и вызывать правильные адаптеры рантаймов.

## Шаги реализации
1.  **Materialization Logic**:
    - [x] Реализовать клонирование Git-репозиториев для сервисов в `prod` режиме.
    - [x] Реализовать вычисление `target_path` для каждого сервиса.
2.  **Orchestration**:
    - [x] Обновить цикл `sync`: для каждого сервиса определять рантайм и вызывать соответствующий адаптер.
    - [x] Интегрировать `Implication Merging` для venv-сервисов (проброс параметров через ENV).
3.  **Verification**:
    - [x] Обновить `EnvironmentInspector` для проверки состояния venv-сервисов.

## Критерии готовности
- [x] `hsm sync` успешно разворачивает локальный venv-сервис.
- [x] Изоляция VES подтверждена автоматизированными тестами.

## Отчет о реализации (Обновлено 2026-02-08)
- **Что сделано**: Полностью реализована поддержка Virtual Environment Services (VES), включая материализацию из Git, разрешение зависимостей и High-Fidelity тестирование.
- **Как реализовано**:
    - **SyncEngine**:
        - Реализовано клонирование Git-репозиториев для сервисов в режиме `prod`.
        - Внедрен полноценный резолвинг зависимостей через `_resolve_package_requirement`. Теперь изолированные сервисы корректно устанавливают локальные библиотеки и Git-зависимости из реестра.
        - Интегрирован механизм `Implication Merging`: параметры из `implies` теперь корректно пробрасываются в ENV изолированных сервисов.
        - Исправлена логика вычисления путей для источников `local`, `build` и `git`.
    - **Registry & CLI**:
        - Расширен `RegistryManager` для поддержки полей `dependencies` и `deployment_profiles` в манифестах сервисов.
        - Обновлена CLI команда `hsm registry service add`: добавлены опции `--runtime` (`-rt`) и `--dependency` (`-dep`) для декларативной настройки сервисов.
    - **Infrastructure & Testing**:
        - Исправлен "пакет-канарейка" (`canary-pkg`): обновлены импорты `hatchling` и структура пакета для корректной работы билд-хуков.
        - Рефакторинг тестов `test_ves_git.py` и `test_ves_env.py`: теперь они полностью полагаются на CLI команды, исключая ручную правку `hsm.yaml`.
        - Внедрена проверка пакетов через `uv pip list --python .venv/bin/python` для гарантии работы в изолированном окружении.
- **Результат**: Все тесты (isolation, git, env, sandbox) проходят успешно. Система гарантирует изоляцию и корректную передачу контекста от манифеста до рантайма сервиса.
