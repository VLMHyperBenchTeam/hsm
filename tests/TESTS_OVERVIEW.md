# Обзор системы тестирования HSM

Этот документ описывает структуру, методологию и подходы к тестированию Hyper Stack Manager (HSM). Система тестирования построена на принципах **High-Fidelity Integration Testing** (высокоточное интеграционное тестирование), что гарантирует работоспособность инструмента в реальных условиях.

## 1. Методология и уровни тестирования

Мы используем многоуровневый подход, разделяя проверку логики и проверку реальных эффектов в системе.

### Уровень 1: Logic Level (Intent)
*   **Инструмент**: `typer.testing.CliRunner`.
*   **Идея**: Быстрая проверка парсинга аргументов, валидации ввода и корректности формирования внутренних структур данных.
*   **Файлы**: `test_cli_basic.py`, `test_cli_project.py`, `test_cli_registry.py`, `test_registry_logic.py`.

### Уровень 2: System Level (Subprocess)
*   **Инструмент**: `subprocess.run(["hsm", ...])`.
*   **Идея**: Проверка того, что установленный пакет корректно работает через `entry_points` и взаимодействует с системным окружением.
*   **Файлы**: `test_system_level.py`.

### Уровень 3: Environment Level (High-Fidelity)
*   **Инструмент**: Реальные `uv`, `git`, `docker` (через `docker compose config`).
*   **Идея**: Проверка реального изменения состояния системы (создание venv, установка пакетов, клонирование репозиториев). Мы не мокаем внешние инструменты, а заставляем HSM работать с ними по-настоящему.
*   **Файлы**: `test_environment_level.py`, `test_ves_env.py`, `test_ves_git.py`, `test_ves_isolation.py`, `test_docker_validation.py`.

## 2. Ключевые паттерны и подходы

### Self-Bootstrapping Sandbox (Самозагружающаяся песочница)
Вместо ручной подготовки файлов для тестов, мы используем сам HSM для создания тестового окружения.
*   **Как это работает**: Фикстура `hsm_sandbox` создает временную директорию и устанавливает `HSM_REGISTRY_PATH`. Тест запускает `hsm init`, `hsm registry library add` и т.д., имитируя полный путь пользователя.
*   **Преимущество**: Гарантирует, что инструмент может использовать то, что сам создает.

### Local-Remote Pattern (Git без сети)
Для тестирования материализации сервисов из Git мы не используем внешние сервера.
*   **Идея**: Git — распределенная система. Любая локальная папка с `.git` является полноценным "удаленным" сервером.
*   **Реализация**: Тест создает временный репозиторий на диске и регистрирует его в HSM через `file://` протокол.
*   **Файлы**: `test_ves_git.py`, `test_environment_level.py`.

### Canary Library Pattern (Библиотека-канарейка)
Для подтверждения того, что переменные окружения (ENV) реально доходят до процесса сборки.
*   **Идея**: Мы используем специальную библиотеку (`tests/assets/canary_pkg`), которая падает с ошибкой при установке, если в окружении отсутствует ожидаемая переменная.
*   **Результат**: Успешный `hsm sync` доказывает, что вся цепочка проброса ENV (от манифеста до build-backend) работает верно.
*   **Файлы**: `test_ves_env.py`.

### Physical Isolation (Изоляция VES)
Проверка того, что Virtual Environment Services (VES) действительно изолированы.
*   **Идея**: Мы проверяем, что `uv` внутри сервиса не видит пакеты из родительского воркспейса, используя флаги `--no-workspace`.
*   **Файлы**: `test_ves_isolation.py`.

## 3. Описание тестовых файлов

| Файл | Что проверяет | Подход |
| :--- | :--- | :--- |
| `test_cli_basic.py` | Базовые команды (`--help`, `init`). | Logic Level |
| `test_cli_project.py` | Управление библиотеками, группами и режимами в проекте. | Logic Level |
| `test_cli_registry.py` | CRUD операции в глобальном реестре. | Logic Level |
| `test_registry_logic.py` | Глубокая проверка логики реестра (группы, опции). | Logic Level |
| `test_system_level.py` | Вызов реального бинарника `hsm` через subprocess. | System Level |
| `test_docker_validation.py` | Валидность генерируемого `docker-compose.hsm.yml`. | High-Fidelity (Docker Config) |
| `test_environment_level.py` | Сложные сценарии: слияние импликаций, гибридные облака, секреты. | High-Fidelity (Sandbox) |
| `test_functional_flow.py` | Полный цикл: init -> lib init -> lib add -> sync. | End-to-End Sandbox |
| `test_ves_env.py` | Проброс ENV и зависимостей в изолированные сервисы. | Canary Library |
| `test_ves_git.py` | Клонирование сервисов из Git-репозиториев. | Local-Remote |
| `test_ves_isolation.py` | Физическая изоляция venv сервисов от воркспейса. | High-Fidelity |
| `test_sandbox.py` | Инструмент для ручной отладки в изолированном окружении. | Manual Debug |
